heed.sinks.github#

A sink that turns a report into a GitHub issue.

The issue-creating call is dependency-injected (create_issue) so the sink is testable without network access and so the credential-brokering strategy (a GitHub App minting short-lived installation tokens, or a server-side token) is pluggable. A convenience factory builds a create_issue from a token via ghapi (lazy import, the heed[github] extra).

Hard platform limit (see misc/docs/design.md): there is no GitHub API to attach an image to an issue. Resolve a screenshot_url (committed-file / attachment-store URL) and embed it in the body; base64 data-URIs do not render.

Route a report to a GitHub issue via an injected create_issue callable.

treatments says, per category, the labels, a title prefix and how much context the issue carries (label_map is the older labels-only spelling and still wins for labels). With list_issues it can also read its issues back as a board’s PublicItem entries: only those carrying public_label, with status from status_labels (or the issue’s closed state) and votes from the 👍 reactions.

Defuse GitHub @mention, #123, issue-URL and SHA references.

A zero-width joiner after @/# stops GitHub notifying a user or cross-linking an issue from the tracker’s account. Only the rendered issue is changed; the stored report keeps the original text.
