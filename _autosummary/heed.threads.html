heed.threads#

Comment threads: a persistent, public, append-mostly conversation per key.

A thread is the list of comments left under one thing (a review page, a video, a document). Anyone who can reach the thread can read it and add to it; only a moderator can delete. This module is the reusable core of that mechanism, independent of what the thread is attached to (heed.review attaches it to a media page):

  • Comment / CommentSubmission – the stored comment and what an untrusted client may send (a name, a body, optionally a position in a media item: at_ms, integer milliseconds, and media, the item’s name).

  • add_comment(), list_comments(), delete_comment() – pure functions over ONE thread’s store, a MutableMapping of {comment_id}.json keys, so a dict, a folder or an S3 dol store all work.

  • Threads are a callable thread -> store: memory_threads() (dicts) or folder_threads() (one folder per thread), so reading a thread never lists

    any other thread.

  • make_thread_router() – GET/POST /threads/{thread} and DELETE /threads/{thread}/{comment_id}, hardened like heed’s ingest endpoint (per-IP and per-thread rate limits, per-thread cap, honeypot, body cap, strict validation).

Who may reach a thread is the host’s decision, passed in as thread_exists: an unknown thread is a 404, so a thread keyed by an unguessable id is a capability.

>>> store = {}
>>> sub = CommentSubmission(author="Noel", body="Nice cut", at_ms=1500)
>>> c = add_comment(store, "t1", sub)
>>> [(x.author, x.body, x.at_ms) for x in list_comments(store)]
[('Noel', 'Nice cut', 1500)]
>>> delete_comment(store, c.id)
True
>>> list_comments(store)
[]

heed.threads.make_thread_router(threads=None, *, thread_exists=<function valid_id>, is_moderator=<function no_moderator>, rate_limiter=None, rate_limit_per_minute=10, thread_rate_limiter=None, thread_rate_limit_per_hour=120, max_comments_per_thread=500, trusted_proxies=(), honeypot_field='website', on_comment=None)[source]#

The HTTP surface of comment threads (threads: thread id -> its store).

GET /threads/{thread} lists, POST /threads/{thread} adds (a JSON body: author, body, optional at_ms and media), DELETE /threads/{thread}/{id} deletes when is_moderator(request) and the request carries the X-Heed-Moderate header. A thread for which thread_exists is false answers 404 to everything, which is how a host makes threads capabilities. A filled honeypot_field is accepted silently and stored nowhere. Behind a reverse proxy, set trusted_proxies or every visitor shares the proxy’s rate-limit bucket.

>>> from fastapi import FastAPI
>>> from fastapi.testclient import TestClient
>>> app = FastAPI(); app.include_router(make_thread_router())
>>> client = TestClient(app)
>>> client.post("/threads/t1", json={"author": "Thor", "body": "hi"}).status_code
201
>>> [c["body"] for c in client.get("/threads/t1").json()["comments"]]
['hi']

heed.threads.token_moderator(token, *, also=None)[source]#

A moderator check that needs a secret the owner types in, not a login.

On an origin shared with other apps, a session cookie is ambient authority: any script running there while the owner is logged in can call the API as the owner. A secret in a request header is not ambient (the review page keeps it in memory, never in storage), so such a script can neither delete comments nor post badged as the owner. also (e.g. email_moderator()) is required too, when given.

Use a random token (secrets.token_urlsafe(24)). This raises the bar, it is not a wall: a hostile script on the same origin can still open the review page in a frame and hook it before the owner types the token, or phish with its own prompt. A dedicated origin for the review app is the real fix.

>>> from types import SimpleNamespace as NS
>>> check = token_moderator("s3cret-token-value")
>>> check(NS(headers={"X-Heed-Moderator-Token": "s3cret-token-value"}))
True
>>> check(NS(headers={}))
False
Return type:

Callable[[Request], bool]
