heed.ingest#

The ingest layer — build a Report from a submission and route it to a sink.

process_submission is the pure, framework-free core (dependency-injected sink, stores, clock, id generator) so it is unit-testable without a server. make_router wraps it in a FastAPI APIRouter you can run standalone (make_app) or include_router into an enlace app. Identity is anonymous by default; pass a user_dependency to bind identity when an auth layer (e.g. enlace_auth) is present.

The router treats every request as hostile (see security.py and issue #5). Checks run cheapest-first so abuse is rejected before it costs anything: CORS preflight → origin allow-list → per-IP rate limit (both before user_dependency) → body-size cap (streamed, before parsing) → form limits → honeypot → bot gate → per-origin rate limit → model validation → screenshot sniffing → screenshot sanitizing (images.py: only the image survives, so polyglot payloads and EXIF/GPS metadata are never stored).

Note

this module does not from __future__ import annotations — FastAPI resolves route-handler annotations against module globals, so the request/response types are imported at module level.

Build a FastAPI APIRouter exposing POST /report (and its CORS preflight).

Run standalone via make_app(), or include_router it into an enlace app. Provide user_dependency (a FastAPI dependency returning a user id or None) to bind identity when an auth layer like enlace_auth is present.

Hardening defaults come from config; any piece can be injected instead: rate_limiter (per client IP), origin_rate_limiter (per Origin) and bot_verifier (by default built from config.bot_secret, i.e. off until a secret is configured) and image_sanitizer (by default from config.screenshot_sanitizer: re-encode with Pillow, else a pure-Python strip). Opt-in console/network capture (config.accept_console/accept_network) is masked by redactor before any sink sees it; a field the config does not accept is never parsed.

Routing is decided server-side, never by the browser: resolve_sink maps the validated origin to that site’s sink (sink is then the fallback and may be None; an origin resolving to no sink gets 403). moderator may hold reports in holding_sink (required with a moderator) or reject them; see routing.py.

Enrich submission into a Report, store any screenshot, and route to sink.

Returns the (report, sink-result) pair. The server owns id/created_at/identity/ origin/status — never the client. Opt-in capture (console/network) is dropped unless enabled in config, and what is kept is passed through redactor (personal data and secrets masked, see redact.py) whatever the widget did. moderator decides first: hold sends the report (status held) to holding_sink instead, reject drops it (status declined).

Return type:

tuple[Report, SinkResult]

Read the request body, or return None as soon as it exceeds max_bytes.

Checks Content-Length first, then counts streamed bytes (a chunked request has no length header), so an oversized body is never buffered whole.
